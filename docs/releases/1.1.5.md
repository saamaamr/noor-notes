# Noor Notes 1.1.5

Patch target after live Snap stable 1.1.4 (revision 23), verified on 2026-09-06. Publication pending verification.

## Fix

The 1.1.4 Dev executable included public Supabase configuration, but the official Snap recipe did not. As a result, the Store build disabled the real Google/email account actions. The Snap recipe now supplies the same public project URL and publishable key at build time. No service-role key or OAuth secret is included, and users must explicitly sign in and unlock a vault before syncing.

## Regression protection

- Snap manifest validation rejects missing account configuration and non-publishable keys.
- A headless `--check-cloud-config` command exercises the production configuration/client path without opening notes, keyring, or a network session.
- Every Snap build/Store smoke path checks the installed binary without environment overrides before publication/promotion.
- CLI tests cover valid, missing, insecure and privileged configuration and ensure keys are not printed.

## Scope

No editor, note format, persistence migration, new dependency, Google Drive or OneDrive configuration change. Sync remains manual and opt-in. Public auth settings confirm Google/email providers enabled; this alone does not prove successful OAuth token exchange or two-device sync. Those live acceptance results remain explicitly tracked in `docs/supabase-staging-verification.md`.
