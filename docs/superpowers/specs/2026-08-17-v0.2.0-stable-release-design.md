# Noor Notes v0.2.0 Stable Release Design

## Goal

Publish the current Noor Notes source as a coordinated v0.2.0 feature release on GitHub and the Snap Store's `latest/stable` channel. Align package versions, public documentation, Store metadata, and Store media so users see one accurate release story.

## Release identity

- Product version: `0.2.0`.
- Git tag: `v0.2.0`.
- Snap track and risk: `latest/stable`.
- Supported Snap architecture: amd64.
- License: `GPL-3.0-or-later`.
- Release date: 17 August 2026.
- Rich Text canvas spacing remains exactly 5 pixels vertically and 8 pixels horizontally.

The minor-version increase reflects substantial user-facing work since v0.1.1: the redesigned library and editors, Light/Graphite/Midnight/OLED appearances, responsive panes and toolbars, Rich Text colours, source editor modes, visible Archive and Trash workflows, and private writing assistance.

## Version consistency

Update the product version in the root Snapcraft recipe, AppStream metadata, Noor workspace package manifests, Cargo lockfile, release workflow expectations, manual Snap workflow artifact naming, and version-specific README copy. Add a v0.2.0 AppStream release entry without deleting the v0.1.1 and v0.1.0 history.

Generalize the GitHub tag release job so any `v*` tag whose value matches both Snapcraft and AppStream metadata can create verified release assets. Do not leave an equality check hard-coded to v0.1.1.

## Public release notes

The v0.2.0 release notes will describe:

- A calm, layered Light Mode and purpose-built Graphite, Midnight, and OLED appearances.
- Adaptive library, note cards, preview panes, editor toolbars, and narrow-window behavior.
- Rich Text, Markdown, Plain Text, and Code modes with persistent formatting and theme-aware source highlighting.
- Offline spelling, offline English grammar, and encrypted local writing predictions enabled by default, with per-note overrides.
- Optional online assistance remaining disabled until explicitly configured and successfully tested.
- SQLCipher local encryption, GNOME Keyring key storage, recovery-aware autosave, Trash restoration, search, sorting, tags, pinning, favorites, and archive controls.
- The strict Snap sandbox limitation for importing host Xpad data.

Do not advertise encrypted synchronization as generally available because the public application still lacks a supported account and vault configuration flow.

## Snap Store textual metadata

- Title: `Noor Notes`.
- Summary: `Private, offline-first notes with powerful editing for Linux`.
- Categories: `Productivity` and `Utilities`.
- Website: `https://github.com/saamaamr/noor-notes`.
- Source code: `https://github.com/saamaamr/noor-notes`.
- Contact and issues: `https://github.com/saamaamr/noor-notes/issues`.
- License: `GPL-3.0-or-later`.

The expanded Store description will lead with native, private, offline-first note-taking and then cover the library, editing modes, writing assistance, organization, appearances, saving/recovery, and encrypted local storage. It will state that online assistance is optional and that Noor Notes has no advertising, analytics, or tracking.

The packaged Snap metadata is the canonical source for title, summary, description, icon, license, website, contact, issue, and source-code fields. Use `snapcraft upload-metadata` on the verified v0.2.0 Snap after upload so the Store text and icon match the package. Categories and media remain dashboard-managed.

## Store media

The public Store listing will contain the existing Noor Notes icon, the 1920 × 640 featured banner, and no more than five 1248 × 702 PNG screenshots. Each screenshot must be captured from the real v0.2.0 GTK application with synthetic notes and no personal data.

The five views are:

1. Light library with sidebar, restrained colour rails, note list, and selected-note preview.
2. Rich Text editor showing the current 5-pixel vertical and 8-pixel horizontal canvas spacing and compact controls.
3. Writing Assistance controls showing local spelling, grammar, prediction choices, and the disabled-by-default online option.
4. Graphite appearance showing the same library hierarchy with deliberate dark-theme contrast.
5. A responsive or source-mode view demonstrating narrow-window behavior or Markdown/Code editing without duplicating the first four images.

Refresh repository screenshot files when an existing image predates the current interface. Add the writing-assistance overview to the AppStream screenshot list and repository gallery. Keep every Store image under the Store's 2 MB media limit. Do not fabricate application states or include unsupported features.

Media upload and category selection use the authenticated Snapcraft listing dashboard. If the existing browser session requires login, password, or two-factor authentication, stop at that boundary and report the exact remaining dashboard actions; do not request or expose credentials.

## README behavior

- Present `sudo snap install noor-notes` as the recommended stable installation.
- Retain edge only as an optional preview/testing channel.
- Update the current release and downloadable artifact instructions to v0.2.0 after the GitHub release exists.
- Update version-specific limitations from v0.1.1 to v0.2.0 when they remain true.
- State the final live Store version, revision, architecture, and channels only after Store verification.
- Preserve alternative downloaded Snap, Flatpak, source, and local-build instructions.

## Build and publication flow

1. Make version, metadata, media, workflow, and README changes on `main` without staging the existing local v0.1.0 or v0.1.1 Snap files.
2. Run formatter, clippy with warnings denied, the full workspace test suite, packaging contract tests, screenshot tests, and diff checks.
3. Build the v0.2.0 Snap, lint it, install it with `--dangerous`, and smoke-test the command before public upload.
4. Commit and push the verified source to `origin/main`.
5. Create and push the signed or annotated `v0.2.0` tag.
6. Wait for the GitHub release workflow; require the Snap job, Flatpak job, and GitHub release job to succeed.
7. Download and checksum the exact GitHub release Snap artifact.
8. Upload that exact Snap to `latest/stable`, allowing the Store's automated review to complete.
9. Upload packaged textual metadata and icon, then update categories, screenshots, and banner in the Store dashboard.
10. Verify `snapcraft status`, `snapcraft revisions`, `snap info`, the public listing, and a stable-channel install or refresh.
11. Update any README Store revision number discovered during publication, rerun documentation checks, and push the final documentation correction if necessary.

## Failure handling

- If local validation or packaging fails, do not tag, upload, or alter Store channels.
- If GitHub Actions fails, do not publish a different local binary; fix the source and create a new release attempt without moving a failed artifact to stable.
- If Snap Store automated review rejects the upload, leave v0.1.1 revision 2 on stable and correct the package before retrying.
- If the v0.2.0 application fails its Store-installed smoke test, do not claim release completion. Restore the prior stable channel revision if v0.2.0 was already released.
- If dashboard authentication blocks media changes, keep the verified package release and textual metadata work, then report the outstanding media/category actions explicitly.
- Never delete or overwrite the user's untracked local Snap packages.

## Verification evidence

Completion requires fresh evidence for:

- Version agreement across Snapcraft, AppStream, Cargo package manifests, Cargo lockfile, workflows, README, tag, GitHub release, and Snap Store.
- Formatter, clippy, workspace tests, security checks, package contracts, screenshot contracts, Snap lint, and Snap smoke tests.
- GitHub release assets and checksums.
- Snap Store automated review acceptance and `latest/stable` mapping.
- Public Store metadata, icon, five screenshots, featured banner, categories, license, and links, subject to the authenticated-dashboard boundary above.
- A clean committed diff with only the two pre-existing local Snap packages untracked.
