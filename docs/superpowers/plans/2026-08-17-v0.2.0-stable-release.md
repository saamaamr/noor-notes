# Noor Notes v0.2.0 Stable Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish one verified Noor Notes v0.2.0 build as a GitHub release and as the Snap Store `latest/stable` revision, with matching documentation, metadata, screenshots, banner, categories, and links.

**Architecture:** Treat the Git tag and CI-built Snap as the release source of truth. First align and test every version/metadata surface, then capture five current synthetic-data screenshots, validate and push the source, let GitHub Actions create checksummed artifacts, and upload that exact Snap to stable. Store dashboard media is the only browser-managed step.

**Tech Stack:** Rust 1.85+, Cargo, GTK4/libadwaita, AppStream XML, Snapcraft 9, GitHub Actions/CLI, Markdown, POSIX shell, Xvfb

## Global Constraints

- Product version is exactly `0.2.0`; tag is exactly `v0.2.0`; release date is 17 August 2026.
- Publish directly to Snap Store `latest/stable` for amd64, as requested.
- Preserve Rich Text canvas margins at exactly 5 pixels top/bottom and 8 pixels left/right.
- Never open, copy, or modify the user's normal Noor Notes database or personal notes during screenshot capture.
- Store screenshots use real v0.2.0 GTK widgets, synthetic notes, 1248 × 702 RGB PNG, and remain below 2 MB.
- The Store listing uses at most five screenshots plus the existing 1920 × 640 banner.
- Do not advertise encrypted synchronization as generally available.
- Do not add dependencies or redesign application behavior for the release.
- Never stage, delete, overwrite, or upload the existing untracked `noor-notes_0.1.0_amd64.snap` and `noor-notes_0.1.1_amd64.snap` files.
- Stop before any Store channel change if validation, packaging, or GitHub Actions fails.
